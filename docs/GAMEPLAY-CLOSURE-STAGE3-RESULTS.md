# 阶段3：经营经济与目标引导

日期：2026-11-16。状态：**已完成并验收通过**。仅本地修改，不发布、不推送，不开始后续阶段。

## 行为与状态

- `ambienceTip(save) = min(6, 六件常规装饰中 owned 与 placed 同时包含的不同ID数量)`。完成订单时采样，不冻结在开始制作时。
- 订单只结算一次，`coins` 和 `earned` 增加商品价与小费之和，`served` 加1。故事仍只发原有12金币，委托不额外发钱。
- 购买、摆放、收起保持原效果与价格，提取为纯规则以验证余额与重复操作。未购买、已收起、重复ID、免费冬季陈设不增加小费。
- 完成反馈第一行分开列出「商品收益 +32 · 氛围小费 +1」，第二行保留人物委托完成，第三行显示本单新触发的待照料/可收获提醒。之后的关键交易消息排队，每项保留6.5秒，不把结算顶掉。
- 原收益容器支持多行并通过浏览器手动Popover放到原生弹窗上方，仍不拦截点击、不抢焦点；无新增常驻面板。
- 菜单/装扮说明当前每单小费；原菜单卡片、四款基础商品和两款新品价格、六件装饰、故事与剧情保持。
- 「下一件小事」共用同一派生函数返回文案/动作：可读故事 → 活跃人物委托 → 首件常规装饰（不足时显示还差几枚）→ 棠姨线 → 花园收获/照料/播种/成长 → 自由经营。同优先级固定阿禾、林伯、棠姨。花园提醒不会抢走可读故事，菜单委托目标、人物卡和花园卡始终各自保留准确状态。

## 存档与事务防护

没有新增存档字段，也不改变键 `glasshouse-stories-v1` 或导出格式。小费不持久化副本，由旧的 owned/placed 推导。旧版、阶段1、阶段2存档读取时原金币、累计收益、已完成订单、章节、菜单和装饰逐值保留，不补发历史小费。

订单在扣库存、推进作物/委托、发放金币之前验证全部数值，拒绝负数、NaN、非整数及安全整数溢出，失败不产生部分状态变更。重复完成不发钱、不扣料、不成长。收获也防护非法库存；12金币故事奖励增加溢出保护，不改正常数值。

## 前30分钟数值检查

方法：使用实际纯规则、冻结的原对话解锁表与原价格，模拟完整操作；另跑浏览器真实8秒订单。这是经济可达性检查，不冒充30分钟真人体验研究。

| 节点 | 计算 / 结果 |
|---|---|
| 最早合理首件装饰 | 阿禾第1章12 + 蜂蜜拿铁32 + 第2章12 = 56；花箱55，剩1。两次故事、一单，无额外刷取 |
| 严格跟随引导才买首件 | 九章108 + 六项委托174 = 282，首件55完全可负担；额外刷单0。优先级未为提早卖装饰而调整 |
| 早点买花箱的完整人物路径 | 六项委托后共九章，余额232（已花55，后五单小费5），花园已开放 |
| 花园首次收获 | 双作物一起播种：两单→照料→一单；共三单收获葡萄3、草莓3，不需等待真实时间 |
| 再各卖一杯新品 | 从新档累计11单：故事108 + 商品334 + 小费10 − 花箱55 = 397；两种库存各余2 |

商品价格保持24/32/38/28，花园饮品42/46；满六件小费后分别30/38/44/34/48/52。小费对每款均等，不改变价差。相对最高基础商品莓果可颂38，两款新品提升4/8（约10.5%/21.1%）。

**经济边界：** 花园新品在纯金币效率上占优；双作物每三单产6份，而三杯新品只耗3份，因此持续照料后可以自给并累积库存，不应把库存描述为永久稀缺。基础菜单仍承担六项专属委托，且不需要播种、浇水、收获或库存管理；缺货时照常经营。本次目标是保留这些玩法用途，不声称四款基础商品在纯金币最大化策略中同等最优。未改既定价格、作物产量或门槛，也没有为了凑30分钟引入等待或减速。
