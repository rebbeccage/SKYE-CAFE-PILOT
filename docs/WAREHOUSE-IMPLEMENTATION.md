# 天空岛 · 仓库实现与验收

日期：2026-11-17。实际源码：`app/src/`。生产产物：`game/`。本地构建，未发布或推送。

## 当前数据与范围

审计确认：现有作物食材存于 `ingredients`，六件常规装饰存于 `owned / placed`。现有订单默认制作 8 秒后自动售出，在完成时扣一次花园食材；未完成的订单不进存档。仓库直接读取这些数据，不另建作物或装饰账本。

本轮仅增加餐品库存 `foodStock?: Record<string, number>`。三位人物、原九章文本、六件装饰价格、七款已实现商品及定价保持；相机、角色、场景模型、天气与渲染不变。

## 玩家操作

1. 主页原「花园」按钮移除，原位置增加藤篮图标的「仓库」。作物热点仍打开原有生长进度面板；「景致」内的花园观察机位保留。
2. 仓库分类：作物、餐品、装饰。数字均为该类数量非零的物品种类数。装饰每个拥有的唯一品种计一种，已摆放也计入。
3. 已收获或已解锁对应配方的作物可在零库存时留下淡色条目。首次收获前不提前展示；空分类显示指定的温柔文案。
4. 选作物可「前往制作」进入现有菜单并选中对应饮品；「前往花园」打开原种植面板。
5. 选装饰可摆放或收起，调用原有规则，同步场景、装扮面板与氛围小费。所有权不改变，不进行二次购买。
6. 冬日免费陈设仍由季节场景管理，常驻规则不变，不伪造 owned 条目、不计入付费装饰库存或小费。
7. 仓库只在物品区域滚动，关闭、分类和选中物品操作保留。手机两列、导航按钮至少 44×44px。原生弹窗锁定背景相机与点击，关闭恢复。
8. 上次分类是 UI 偏好，保存为 `skye-warehouse-tab`；它不是库存或进度，保存失败不影响使用。键盘左右/Home/End 可切换分类，Esc 可关闭。

## 制作去向与事务规则

| 行为 | 食材 | 餐品库存 | 金币/小费 | 人物委托 | served/作物生长 |
| --- | --- | --- | --- | --- | --- |
| 制作并售出（原默认） | 完成时扣一次 | 不变化 | 完成时按原规则结算 | 只推进选中的正确委托 | 按原规则推进 |
| 自由制作后入库 | 完成时扣一次 | 对应品种 +1 | 不发金币、不发小费 | 不推进 | 不推进 |
| 仓库售出餐品 | 不再次消耗 | 扣所选数量 | 当前售价 × 数量 + 当前摆放氛围小费 × 数量 | 不推进 | 不推进 |

- 入库仅允许显式选择「自由营业」；人物委托模式禁用入库。菜单制作前显示去向、食材数量与当前库存。
- 两种制作沿用原 8 秒流程。开始制作只生成内存中的订单计划，完成时才提交。刷新取消未完成制作，不丢食材，也不补出餐品。
- 入库制作不算接待客人，因此不推进已售单数、Mona 的六单门槛或作物生长。仓库出售也不补算这些事件，避免对既有节奏重复计数。
- 完成使用订单 `committed` 标记保证仅一次提交。入库前检查库存整数、食材与数值溢出，失败不部分写入。
- 库存出售直接读取原商品目录价格，按出售时已购买且正在摆放的常规装饰计算每份 0–6 小费；商品收益与小费分开展示。
- 售出数量须为正安全整数且不超过库存。检查预期库存，拒绝陈旧点击；界面同时有 600ms 双击保护。全部校验通过后同步扣库存与加金币，零数量移除条目。
- 制作中保持原导入保护，异步文件读取仍受订单 epoch 约束，避免恢复存档覆盖进行中的交易。

## 存档

- 原 key `glasshouse-stories-v1` 与导出格式 `glasshouse-v1` 保留。
- 旧档无 `foodStock` 时默认为 `{}`，绝不把历史已售订单变成库存。
- 只接收当前目录的七种餐品 ID 和有效非负安全整数；负数、小数、非数值、未知 ID 独立丢弃，不清空其他进度。
- 作物仍用 `ingredients`，装饰仍用 `owned / placed`，仓库没有同步副本。
- 制作完成、出售、摆放、收起通过原 persist 更新余额与场景。仓库开启期间制作结束会刷新当前分类。
